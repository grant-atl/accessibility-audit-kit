# WCAG 2.2 coverage matrix

Verified against [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and the linked W3C Understanding documents on **2026-09-28**. This table has **86 current success criteria: 31 A, 24 AA, and 31 AAA**. Obsolete 4.1.1 Parsing is excluded. The test descriptions are original operational summaries; the normative criterion, definitions, and exceptions control a conformance decision.

Assess every row for every page and state in the declared inventory. A complete review includes AAA coverage, but an **AA conformance target consists of the 55 A and AA criteria**; report the 31 AAA results separately as supplemental unless AAA is explicitly the target. A criterion level is not issue severity. Never describe an AAA failure as an AA failure merely because both rows were tested.

Record evidence and status per page/state/criterion. Use N/A only with a concrete reason, such as absence of time-based media; unavailable credentials, tools, devices, or evidence mean untested/blocked, not N/A or pass. When a criterion applies but a defined exception is satisfied, document the exception and evidence. Shared evidence may be referenced by multiple rows only when its applicability to each page/state is established. Cross-page criteria need linked comparison evidence, not isolated screenshots.

Evidence methods below are complementary:

- **Automation candidate:** a scanner, DOM query, measurement, or test can find some failures; a clean result does not establish the whole criterion.
- **Manual:** operate and inspect the actual rendered state, including responsive variants, errors, overlays, and content changes.
- **AT:** use the real supported assistive technology. For VoiceOver, record macOS/iOS, browser and versions, navigation mode, action, and actual announcement; a DOM or accessibility-tree snapshot alone is not a VoiceOver test. Include other claimed browser/AT combinations where applicable.
- **Specialist:** content, language, captioning, audio, or flash analysis beyond a basic page scan. If unavailable, preserve the coverage row as untested.

Page title and language metadata, input-purpose tokens, and accessible names are covered below. SEO descriptions, social-preview tags, and other metadata are not automatically WCAG obligations. Beyond these rows, evaluate WCAG's [conformance requirements](https://www.w3.org/TR/WCAG22/#conformance-reqs): target level, full pages, complete processes, accessibility-supported technologies, and non-interference. A component or page sample cannot establish an unexamined site's conformance.

| 3.2.6 | A | Consistent Help | Across pages with repeated contact details, contact mechanisms, self-help, or automated contact, compare their order relative to other content. Verify consistency unless the user changes it; this criterion does not require adding a help mechanism. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/consistent-help.html) | Manual cross-page/reading-order comparison + AT |
| 3.3.1 | A | Error Identification | Submit missing and invalid values. For automatically detected errors, verify the affected item is identified and the error is described in text, not only color; inspect association and announcement through related semantic criteria. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) | Manual invalid-input test + AT + automation candidate |
| 3.3.2 | A | Labels or Instructions | For every user-input field/group, verify labels or instructions explain what is required, including needed format and required status. Check persistent understandable visible information as well as programmatic names; placeholder-only input needs scrutiny. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) | Manual form/content review + AT |
| 3.3.3 | AA | Error Suggestion | Trigger errors with known corrections and verify the user receives useful correction guidance, unless that would undermine security or purpose. Confirm suggestions match the actual accepted data. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html) | Manual invalid-input/correction journey + AT |
| 3.3.4 | AA | Error Prevention (Legal, Financial, Data) | With synthetic data, test legal/financial submissions, changes or deletion of user-controlled stored data, and test responses. Verify at least one safeguard: reversal, error checking with correction, or review/confirmation/correction before finalization. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html) | Manual safe transaction/review/undo test + AT |
| 3.3.5 | AAA | Help | Find and use context-sensitive assistance for the task or input, where needed. Verify the help describes the current problem and is reachable with keyboard and AT rather than merely linking to unrelated generic content. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/help.html) | Manual task/help review + keyboard + AT |
| 3.3.6 | AAA | Error Prevention (All) | For every page requiring submitted information, verify reversal, checked/correctable data, or review/confirmation/correction before finalization. Unlike 3.3.4, do not limit the inventory to consequential transaction types. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-all.html) | Manual synthetic-data submission/review/undo + AT |
| 3.3.7 | A | Redundant Entry | Complete each multi-step process; when information already supplied by or to the user is required again, verify autofill or selection is available. Record essential, security, or no-longer-valid-information exceptions. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html) | Manual full-process test + AT |
| 3.3.8 | AA | Accessible Authentication (Minimum) | Test every authentication, MFA, and recovery step with password managers and paste/autofill. Any cognitive test needs an allowed alternative, assisting mechanism, object-recognition, or personal-content provision; examine the full path, not just the password field. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html) | Manual authentication journey + password manager + AT |
| 3.3.9 | AAA | Accessible Authentication (Enhanced) | Test every authentication step for a path without a cognitive-function test, or a mechanism that assists with the test. Do not use AA 3.3.8's object-recognition or personal-content exceptions for this criterion. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-enhanced.html) | Manual authentication journey + password manager + AT |
| 4.1.2 | A | Name, Role, Value | Inspect and operate every control, including custom and embedded widgets. Verify exposed name/role, user-settable states/properties/values, and notification of changes; compare accessibility-tree data with actual AT announcements and interaction. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) | Automation candidate + accessibility-tree review + AT |
| 4.1.3 | AA | Status Messages | Trigger success, progress, waiting, result counts, validation summaries, and other qualifying status changes without moving focus. Verify roles/properties expose these messages to AT and actual announcements convey them without unnecessary focus changes. [Guide](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) | Manual dynamic-state test + AT announcements |
